# E2E-тесты LuCI для OpenWrt

Тесты проверяют установленный веб-интерфейс LuCI в настоящем OpenWrt с помощью
двух Docker-контейнеров:

- OpenWrt x86_64 с `procd`, `ubus`, `rpcd` и `uhttpd`. В него устанавливаются
  собранные в одном SDK APK пакетов AntiBlock и LuCI.
- Отдельный контейнер Playwright с Chromium. Он запускает `browser.js` и
  проверяет поведение LuCI через настоящий браузер.

На хосте не требуется устанавливать Python, Node.js, Chromium, Playwright или
npm. Для этапа запуска E2E достаточно Docker. При сборке APK также нужны
обычные зависимости общего сборщика `openwrt-package-ci`.

## Требования

- Docker с работающим демоном и доступ к Интернету для загрузки образов.
- Соседний каталог `openwrt-package-ci` с общим `openwrt-build.sh` либо
  переменная `OPENWRT_BUILD_SH` с путём к этому скрипту.
- Стандартные зависимости сборщика OpenWrt SDK, если APK ещё не собраны.

## Запуск

Из корневого каталога репозитория LuCI:

```sh
OPENWRT_VERSION=SNAPSHOT sh tests/run.sh
OPENWRT_VERSION=25.12-SNAPSHOT sh tests/run.sh
OPENWRT_VERSION=25.12.6 sh tests/run.sh
```

По умолчанию используется `SNAPSHOT` - текущая основная ветка OpenWrt.
Значение `master` намеренно отклоняется: нужно передавать `SNAPSHOT`.

Сборщик собирает `luci-app-antiblock`. Пакет AntiBlock автоматически
собирается из стандартного `packages` feed как зависимость `LUCI_DEPENDS`.
Отдельно запускать сборку AntiBlock не нужно.

Для проверки уже собранных APK архитектуры **x86_64** можно пропустить SDK:

```sh
E2E_LUCI_APK=/path/to/luci-app-antiblock-0.apk \
E2E_ANTIBLOCK_APK=/path/to/antiblock-3.0.0-r1.apk \
OPENWRT_VERSION=SNAPSHOT sh tests/run.sh
```

Необходимо передавать оба APK, собранных для совместимой версии OpenWrt.

## Тестовое окружение

`tests/run.sh` выбирает версию OpenWrt и либо собирает LuCI в SDK, либо
использует готовые APK. Затем `tests/run-runtime.sh`:

1. Подготавливает официальный rootfs OpenWrt в Docker.
1. Устанавливает оба локальных APK и необходимые зависимости.
1. Запускает OpenWrt с `procd`, `ubus`, `rpcd` и `uhttpd`.
1. Подготавливает UCI-конфигурацию, файл доменов, журнал и статистику.
1. Запускает Chromium и `browser.js` в отдельном контейнере Playwright.

Для браузерного теста используется официальный образ
`mcr.microsoft.com/playwright:v1.64.1-noble`, в котором уже есть Chromium и
все необходимые системные библиотеки. Его не требуется скачивать заново,
если он уже находится в Docker.

В этом образе нет JS-модуля `@playwright/test`. Поэтому при первом запуске
создается один локальный дочерний образ с этим модулем из npm. Никакие браузеры
отдельно не устанавливаются. При последующих запусках Docker использует
закешированный дочерний образ. На Arch Linux ничего устанавливать не нужно.

Здесь нет дополнительных проверок и переустановок npm при каждом запуске:
если создать образ не удалось, тест сообщает об ошибке и завершается.

## Проверки

E2E-сценарий проверяет:

1. Установку пакетов AntiBlock и LuCI из одной сборки OpenWrt SDK.
1. Запуск `procd`, `ubus`, `rpcd`, `uhttpd` и доступность LuCI по HTTP.
1. Авторизацию root через HTTP ubus и в браузере.
1. Чтение настроек Args из UCI, отклонение неверного `listen` и сохранение
   корректного значения в UCI.
1. Отображение пути доменов из настроек Routes.
1. Чтение и изменение реального файла доменов через RPC с сохранением пустых строк.
1. Отображение реальных файлов журнала и статистики. Файлы подготавливаются
   через `docker exec` до запуска браузера, а проверяются до изменения
   конфигурации и перезапуска AntiBlock. LuCI не получает права на запись
   журнала и статистики или остановку службы ради тестов.
1. Отсутствие необработанных JavaScript-ошибок в браузере.

Здесь нет подменённых API или отдельных unit-тестов. Проверяются реальные
службы OpenWrt и установленный веб-интерфейс LuCI.

## Диагностика

После входа в LuCI независимые проверки продолжаются даже
при отдельных ошибках, чтобы за один запуск собрать все замечания. При
неуспехе в `tests/.artifacts/` сохраняются `failures.txt`, снимки экрана
`failure-*.png` и HTML страниц `failure-*.html`.

Для сохранения снимков экрана установите `E2E_SCREENSHOTS=1`. Снимки при
ошибках сохраняются и без этой настройки. Результаты находятся в
`tests/.artifacts/`.

```sh
E2E_SCREENSHOTS=1 OPENWRT_VERSION=SNAPSHOT sh tests/run.sh
```

Для сохранения временных контейнеров OpenWrt после проверки укажите `E2E_KEEP=1`:

```sh
E2E_KEEP=1 OPENWRT_VERSION=SNAPSHOT sh tests/run.sh
```

GitHub Actions не изменяются. Полный Docker E2E в окружении подготовки
этого архива не запускался.
